# Fishing expedition v2

The 0.4 expedition was a short three-island sword sequence. Version 0.5 adapts
How to Fish's catch–fight–sell–upgrade loop into one temporary solo ArcEvents
match. It uses Minecraft creatures and existing ArcEvents firearms, not the
original game's assets or an exact simulation of its physics.

## Research and adaptation

- [Dazed Games' Steam description](https://store.steampowered.com/app/4001890/How_to_Fish/)
  establishes living catches, selling, gear upgrades, NPC tasks, bosses, island
  progression and rare variants.
- [Firsthand PC Gamer coverage](https://www.pcgamer.com/games/sim/the-latest-cooperative-craze-is-a-physics-based-fishing-simulator-where-you-can-launch-your-catch-into-the-air-and-no-scope-it-with-a-sniper-rifle/)
  describes starting with basic supplies and progressing from fists, knives and
  knuckles to firearms.
- [Steam player walkthrough](https://steamcommunity.com/sharedfiles/filedetails/?id=3788027308)
  documents dynamite, boss bait and trophy hand-ins. Its patch-sensitive shop
  prices are not copied; expedition prices have a separate balance assessment.
- Paper integration targets the existing 1.21.11 API and arc-core 2.7.11.
  [Item pickup controls](https://jd.papermc.io/paper/1.21.11/org/bukkit/entity/Item.html)
  are used to keep thrown dynamite out of inventories. Gun rays, ammunition,
  reload timing and block occlusion remain in the existing TTT firearm owner.

Five islands have three ordinary species each and a boss. Normal catch kills
fill a bag and advance the island task. The trader exchanges the completed
task for boss bait. The next catch summons that island's boss; defeating it
awards a trophy, which must be handed in before travel or final completion.
Extra catches remain possible to fund different equipment choices.

The armory contains knuckles, knife, machete, Five-Seven pistol, double-barrel
shotgun, G36 burst rifle, AEK-971 and McMillan sniper rifle. Buying gear equips
it; travel never grants free upgrades. Switching a previously owned gun keeps
its loaded rounds. Spare ammunition uses the common match-tagged inventory.
Melee remains available when ammunition runs out.

Catch sales, food, two rod upgrades and dynamite are expedition-only choices.
Dynamite is a timed throw with creature damage, self-damage and water-fishing
utility. It does not invoke a native TNT explosion or mutate blocks. All
entities, casts, hits, pending effects and shop callbacks are fenced to the
current owner, world, match, stage and state.

## World and configuration migration

`arcade.fishing.arena.world` remains configurable. The new default is
`arcevents_fishing_v2`, with template marker `fishing-v2`; the lab profile uses
`arcevents_lab_fishing_v2`. The five island centers are x=0/48/96/144/192.
Existing v1 worlds are retained, and their existing chunks are not overwritten.
The retired marker resolves an empty border generator if another plugin loads
that world. Reusing a v1 world as the v2 target is rejected by the provisioner's
marker check.

`arcade.fishing.prices`, sale values, rare interval, boss credits and dynamite
damage are explicit configuration. Rule changes may reload only when idle;
world identity requires restart. The default run limit is 1800 seconds.
Session coins, inventory and catch bag are discarded on completion or failure;
the existing durable escrow restores the player's original state and origin.

## UI and economy

The existing native dialog runtime owns the trader (`events.fishing.trader`)
and armory (`events.fishing.armory`). Entry is the marked barrel under the
canopy or the ledger near the stall. A stale screen cannot transact against a
new run or changed snapshot. Available purchases, owned/equipped choices,
locked islands, balance, task and session-only consequences are explicit.
RU and EN are maintained together.

The [balance model](fishing-v2-balance.json) separates temporary expedition
credits from Vault, premium tokens, EMC, item exports and vanilla XP. None of
those external currencies or exports are emitted. Sales destroy the carried
catch and eating destroys the same catch, so a catch cannot serve both flows.
Prices are progression tuning rather than an exchange rate into the network.

## Verification boundary

Focused verification covers pure progression and economic transitions,
generator geometry, item tagging, firearm/ammunition boundaries, native dialog
models, runtime encounter/trade cleanup and existing shared lifecycle paths.
The exact commands and outcomes are recorded with the immutable candidate.
MockBukkit and geometry checks do not establish native client appearance,
physics feel, actual bite timing or the difficulty of a human playthrough.
Runtime activation is recorded separately in the ops knowledge inventory.

On 2026-09-22, 108 distinct focused cases passed across the selected suites;
failed and changed cases were rerun, with zero failures and zero skips in each
suite's final result. The full expedition scenario runs under
`failOnUnsupportedMockBukkitOperation`, including five trophy hand-ins, shop
transactions, stale snapshots, magazine preservation, thrown-item policy,
water dynamite, escaped-boss recovery, final entity cleanup and original player
state restoration. Explicit test doubles cover only the pinned MockBukkit
TextDisplay billboard/shadow and Item pickup/owner methods it does not implement.
The ten affected runtime/lab YAML files passed syntax validation, and the
economy evaluator output matched the recorded balance result.
