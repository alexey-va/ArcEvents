# Islands of the Deep — 2026-09-22

ArcEvents 0.4.0 adds `FISHING`: one player fishes, fights the catch, completes
three generated islands and defeats the final guardian. Entry is the native
`EventsView.Fishing` dialog (`events.fishing`) or `/arcevents fishing`.

## Ownership and integration

`ArcadeSession` remains the match owner. It reuses the existing durable
`PlayerStateEscrow`, network return route, arena lease and chat isolation.
`FishingProgress` owns progression without Bukkit; `FishingAdventure` owns the
temporary hooks, encounters, travel marker and attack telegraphs. ArcFarms'
existing fishing rescue mechanic has different progression and ownership, so
it is not a suitable owner for this isolated event.

Requester-only Redis reservation atomically selects the requesting player's
own queue row, regardless of FIFO position. It cannot recruit other queued
players. Host and relay availability are mode-aware. The existing host runs
one event at a time; this release does not add concurrent personal instances.

`fishing-v1` is a deterministic, bounded, dedicated arena generator. The host
provisions the configurable `arcade.fishing.arena.world` (default
`arcevents_fishing`); relays do not create worlds. Existing world ownership
markers prevent adopting an unrelated world. Map identity needs restart;
validated fishing rules reload while idle and cannot change mid-match.

Only the participant's bound hook in the current water zone counts. Vanilla
catch drops are removed and catch XP is zeroed. Owned mobs have no native AI;
only the participant's bound expedition weapon can reduce encounter health.
They are removed instead of killed through vanilla loot/XP processing. Missing
encounters resume with their existing progression and health. A single
nonpersistent TextDisplay marks travel, within the small-scene exception;
attack and fishing-zone hints use particles without additional entities.

Timeout, defeat, leave, disconnect and shutdown close the adventure before
restoration. Recycled hook/entity events cannot advance the next match. Two
related lifecycle fixes restore departing reservation arrivals immediately and
retry failed outbound reservations while the player remains online, with
single-flight guards and durable route revalidation.

## Economy assessment

Before and after: no new Vault coins, premium tokens or EMC are emitted by the
new mode. All rods and weapons are temporary escrow-owned event gear. No fish,
vanilla XP, mob loot, command rewards or permanent items are awarded. Existing
statistics may record a completed game/win; no earning multipliers, reward
probabilities or sale/contract rules change. EconomyShopGUI SELL-to-contract
plans are unaffected. This assessment covers the owned event paths, not a
claim about every external plugin's arbitrary event listener.

## Verification boundary

Focused domain, geometry, locale, queue/CAS, coordinator, menu, isolation and
MockBukkit lifecycle checks cover the change. A full three-island catch/fight
scenario exercises actual Paper event handlers and recovery, with synthetic
fishing hooks and damage input. The test world supplies stateful implementations
of MockBukkit's missing distance-despawn and pickup policy setters; combat and
recovery use the actual plugin handlers. Native fishing timing, final map appearance and human
combat acceptance still require a real Minecraft client. No broad Docker or
disposable Redis integration suite is part of this development check.

Live artifact, activation and health evidence is recorded separately in the
ops repository's `docs/knowledge/parkour-events.md`.
