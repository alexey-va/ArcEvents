# Rotate the Apocalypse world on Parkour

`/events admin apocalypse-reset-plan arcevents_apocalypse_s2` is a read-only check for a proposed name. Run it on the Parkour HOST as an administrator or from its console. It inspects the running ArcEvents state and the two destination paths.

## Read the plan

- `arc_ready=true` means the ArcEvents checks passed at the time of inspection. Verify the separate My_Worlds checks below before switching.
- `occupants` includes staff visiting with their regular inventory. Ask participants to use `/events leave` and move visitors back to an ordinary world. Let transitions and checkpoint writes finish, then repeat the plan.
- `active_records`, `returning_records` and `pending_returns` include offline players. Keep their records. A matching native session resumes with its expedition gear in the new bunker. Pending origin restores and transfers use the saved receipt and the existing Redis nonce. A parked expedition keeps its equipment and starts at the new bunker on its next entry.
- `origin_locations` and `origin_compasses` count normal-state receipts that still need the retiring world. The check includes PARKED receipts because a stale native session can replay them. Up to five affected UUIDs appear in `affected_sample`. For a staff visit, restore or leave normally, move to an ordinary Parkour world with a compass target outside the expedition, and complete one normal entry and return. Repeat the plan. Investigate unreadable receipts using their recovery records.
- Resolve every listed blocker. An existing world directory, checkpoint directory, loaded world or configured arcade arena needs a different, unused name. The V1 name is a compatibility alias for V2. An unsafe directory, an incorrect source marker or a changing player snapshot requires investigation or a fresh reading.

## Apply an owner-approved rotation

1. Choose the new name and seed. Keeping the seed rebuilds the same layout with fresh terrain, containers and progress. Changing it selects a different generated layout. Record the current name, seed, generator marker and My_Worlds autoload setting for rollback.
2. Confirm the new name has no existing My_Worlds registration or startup binding. Inspect the native world list and the HOST's current `plugins/My_Worlds/worlds.yml`. Set `my_worlds:world setautoload no <old-world>` and verify the setting. Leave the active world loaded until normal shutdown. A fresh, unregistered name lets ArcEvents install its generator marker before creating the world.
3. Keep new expeditions and staff visits out during the cutover. Repeat the plan with the exact approved name immediately before stopping Parkour. Use the published ops checkout's `./scripts/mc restart --no-notify --stop parkour` for maintenance and verify the full-stop result. Parkour's launcher normally restarts Java after three seconds. If admissions cannot be fenced, compare the player journal file list and hashes before the final plan and after shutdown. A change requires reviewing the new state on the old configuration.
4. Preserve the previous world folder, `plugins/ArcEvents/data/apocalypse/world-<old-world>/`, the shared `data/apocalypse/players/` under ArcEvents, vanilla `world/playerdata/` and Redis. Keep a recoverable copy of the old configuration, world and checkpoint. Base the scoped config change on the HOST's actual `plugins/ArcEvents/apocalypse.yml`, retaining all settings except `world` and the optionally chosen `seed`. Deliver the reviewed configuration with `./scripts/mc push --no-reload parkour -- plugins/ArcEvents/apocalypse.yml`, record its rollback ID and read back both values. Start Parkour with `./scripts/mc restart --no-notify --wait parkour`. ArcEvents reads the world configuration at startup.
5. Verify ArcEvents logs the new world and `apocalypse-original-v1`. Check `my_worlds:world list` for the old world in the **Unloaded** state and keep it unloaded. `Stand-by` means it is still loaded. From a QA player, `/events apocalypse qa` must report the new name, `ready=true`, initial day 0 and fresh structure state. Enter through the ordinary menu, check bunker floor and headroom, open a fresh supply container, then leave and verify the player's original inventory, location and backend return.

The rotation resets world edits, opened containers, mined resources, the day counter, hordes, infections, bunker switches and spawners. Expedition gear and ordinary player inventories keep their own recovery paths. Existing source archives in the ArcEvents cache are reused.

For rollback, stop admissions and check that any normal-state receipts created during the new generation can be restored without that world. Run the plan against a fresh unused candidate to inspect these receipts. Disable autoload for the newer world and restore the previous world's original setting. Return the saved configuration under the same Parkour maintenance procedure and keep both world folders and checkpoints. Restart and verify that the previous generation is active, the newer world is unloaded and an ordinary player can enter and return.
