# ArcEvents review — 2026-09-22

Scope: TTT, GunGame and Disasters domain/lifecycle, network reservations and
returns, escrow ownership, arena boundaries, commands/menus/locales, Paper chat
packets, and the companion ProxyARC audience boundary. Reward amounts and economy
rules were not changed. This is a source/component review, not proof that every
possible gameplay fault is absent.

## Chat contract

Paper suppresses outside player, disguised, system chat and action bars while
ArcEvents owns a participant. Event messages use the documented
[PacketEvents silent transport](https://docs.packetevents.com/sending-and-simulating-packets/).
The installed CMI 9.8.10.0 JAR was inspected directly (SHA-256
`e2fadb1b5093dce041e64267810d4dfdc810b368d103552b0dfc0ff613a733a1`).
Its Paper Bungee handler uses MONITOR with `ignoreCancelled=true`; cancelled
ArcEvents chat is not forwarded. CMI mute handlers remain authoritative.
Already-displayed client chat history is not erased. Titles, boss bars, dialogs
and disconnect reasons are outside this chat-only filter.

ProxyARC uses `modules/event-chat.yml` (`enabled`, `allowed-servers`). The default
list contains the current host `parkour`; routing logic has no fixed server name.
Allowlist changes apply through `/proxyarc reload` and revoke removed-server leases.
HOSTs send `[version=1, active=0/1]` on `arc:events_chat`, renewing every five seconds.
The proxy consumes the channel before validation, accepts only the player's exact
current backend connection, and uses a monotonic 15-second expiry. Leave,
transition, disconnect and shutdown clear ownership. This follows the
[Velocity plugin-message trust boundary](https://docs.papermc.io/velocity/dev/plugin-messaging/).
The narrow security scanner returned zero leads; source identity/expiry tests,
not this scanner result alone, establish the implemented controls.

ProxyARC's own broadcast and direct-message paths obey the filter. Independent
Velocity plugins do not pass through ProxyARC and need a separate integration;
the public Velocity API does not provide a universal outgoing-chat interceptor.
The lease deliberately expires open if the host stops renewing, so it cannot
silence a player indefinitely after a host failure.

## Verification and residual limits

Focused component tests cover packets, proxy lease lifecycle, menu routing,
locale parity, real MockBukkit round recovery and Redis CAS transitions. Domain,
arena and arcade regression evidence is retained from this review. No disposable
Redis integration lane or human-client multiplayer round was run. Live activation,
artifact hashes and readiness belong in the ops delivery record separately.

A remaining P2 architecture risk is synchronous journal I/O in the existing
`PlayerStateEscrow` capture/restore path: a slow disk can stall the server thread.
This patch preserves its durability barrier and removes the explicit network
`get()` on shutdown; it does not convert the complete escrow lifecycle into an
asynchronous state machine. Such a conversion must cover delayed completion,
disconnect and shutdown without moving Bukkit state access off its owning thread.
